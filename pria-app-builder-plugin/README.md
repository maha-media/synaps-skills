# pria-app-builder 0.2.0

Nine typed gateway tools and four shipped runbooks for managed React/Vite dev,
trusted builds and authorized retained Pria Sites releases. No direct guest
HTTP client, arbitrary extension loading or shell service launcher.

## Delivery

Marketplace source is `./pria-app-builder-plugin`; the guest bake list copies the
whole directory, including adapters, profile, scripts and pack.json. Python uses
stdlib only. Vite dependencies belong to the caller app, not this plugin: exact
Vite 8.2.0, plugin-react 6.0.5, parse5 7.3.0 plus app React dependencies and npm
lockfile; Node 22.12+ (22.x) or 24+. Preparation copies the shipped adapter/config
into authorized app source with `python3 scripts/prepare-profile.py "$APP_DIR"`.
It never installs dependencies or overwrites existing config/manifest. It copies
explicitly pinned sibling adapter assets into `pria-adapters/`. Exact manifest,
lock root and locked package versions are checked. Declare `pria.requiredChecks:
["test"]` and a real test script; missing checks refuse, not marker-test bypass.
Script differences produce an explicit proposed manifest diff and refusal.
Required scripts: `dev: vite --configLoader runner`,
`build: vite build --configLoader runner`. Review/apply changes explicitly. Follow dev skill
for authorized dependency preparation BEFORE source snapshot. No installed-path
imports survive into the task. No test fixture paths are needed at runtime.

## Operations

`app_dev_start {workdir,command,readiness?,env?}`, `app_dev_stop
{serviceId,generation}`, `app_service_status {serviceId}`, `app_service_logs
{serviceId,cursor?,limit?}`; `app_build_seal {build,allocateOnly:true}` then
`{build,workdir,outputDir,builder,navigationPaths?}`; `app_release_start
{revisionId}`; publish/rollback `{revisionId,expectedHead:{revisionId,generation}}`;
release stop `{serviceId,generation}`. Results are bounded/redacted backend data,
not synthesized acceptance. Publish returns url/publishedHead, not siteUrl.

Profile `react-spa-relative-v1`, build base `./`, sourceBuildV1 required for actual
built-source lineage. Trusted commands are exactly
`[["npm","test","--","--run"],["npm","run","build","--","--outDir","/output"]]`.
Prepared source must be committed through the authorized workflow before seal;
the guest builds pinned Git HEAD, never dirty edits. Source/dependencies are
read-only; output is fresh and isolated. Node must map builder.commands to guest buildCommands and
verify returned source bytes. Unsupported runtime fails closed. Pack descriptor
is generated by `python3 scripts/pack.py > pack.json`; digest excludes pack.json,
tests and Python caches and hashes sorted `[path,sha256]` tuples as compact UTF-8
JSON. This detects payload drift, not authenticity. Trusted health/admission must
pin name/version/profile/digest server-side; caller claims are not accepted.
Existing manifest empty-only tools/skills and fixed plugin allowlist stay intact.

## Verification (inert)

`bash scripts/test.sh` runs strict plugin lint, unit tests and framed stdio smoke.
Packaging tests copy the payload into a disposable directory, verify descriptor
and profile preparation and never run an installer or contact a real backend.
This is NOT actual VM/browser/deployment acceptance. See each skill for checks,
explicit Collect separation, uncertain publication handling and capability gates.

Focused existing-dependency test: `node tests/profile.mjs /path/to/node_modules`.
During adapter development only, `--snapshot` regenerates the descriptor inside
a disposable copy and labels the result INTERIM; it cannot verify final pack pins.
This invokes the shipped preparation helper, actual npm test/build and managed
Vite dev HTTP; it is not whole guest isolation or opaque browser certification.
