# tode plugin

Make Synaps a better pair programmer inside [terminal-code](https://terminal-code.com) (`tode`). The skill teaches Synaps how to detect a tode-integrated terminal, keep its work visible in the current VS Code workbench, preserve the nested terminal layout, and troubleshoot the shared code-server runtime safely.

## What it enables

When the skill is active, Synaps can use tode's supported CLI bridge to:

- open a changed file in the current workbench;
- jump directly to a diagnostic line and column;
- show a real two-file diff;
- focus the Source Control view for review;
- add or replace workspace folders intentionally;
- distinguish outer tode splits from command-worker panes;
- install extensions into tode's actual shared profile;
- diagnose bridge, shortcut, theme, daemon, and rendering problems without editing generated state.

It also tells the agent to refresh machine-specific knowledge with `tode --skill`. That command is generated by tode itself and reports the current install paths and live runtime state, so the marketplace skill does not bake in one machine's XDG paths or version numbers.

## Install

Install `tode` first if needed:

```bash
curl -fsSL https://tode.sh/install | bash
```

Then install this plugin from the `synaps-skills` marketplace using Synaps' `/plugins` screen. For local development, copy `tode-plugin` into:

```text
~/.synaps-cli/plugins/tode/
```

Installed marketplace plugins are snapshots; update them through `/plugins` after a new release rather than editing the installed copy.

Start Synaps from a tode integrated terminal:

```bash
tode /path/to/project
# In tode: Terminal → New Terminal
synaps
```

Load the skill explicitly with `/tode`, or let Synaps select it when your request involves working in terminal-code. The stable tool identifier is `skill.tode:tode`.

## Recommended workflow

Ask naturally:

- “Open the failing test at the assertion after you fix it.”
- “Show me the diff in tode and switch to Source Control.”
- “Keep this Synaps terminal where it is; open the worktree in a right split.”
- “Why is this shortcut not reaching VS Code?”
- “Check the tode daemon and editor profile without restarting anything.”

The core bridge commands are:

```bash
tode path/to/file
tode --goto path/to/file:42:7
tode --diff /tmp/before path/to/file
tode --review
tode --skill
```

## Design notes

The skill follows terminal-code's actual architecture:

- `TODE_IPC` is injected into integrated terminals by tode's bridge extension.
- File, goto, diff, workspace, and review requests are JSON messages sent over that window's Unix socket.
- One warm code-server and an injecting loopback proxy are shared by windows.
- terminal-browser owns the outer terminal pane; a tode split is therefore different from a VS Code editor split or a tmux worker pane.
- Profile and daemon locations are XDG-aware and may be overridden, so `tode --skill` is the source of truth.
- Generated bridge/theme extensions, injected CSS, and daemon records are tode-owned and should not be hand-edited.

Repository research for the initial skill targeted terminal-code commit `f1b5ee3789739b77310d8ecbf7bdf9513e9e0c2a` and terminal-browser commit `9265a06fb875e5ed810359bbf007bd46d1156a3a`.

## Requirements

- terminal-code with `tode --skill` support (tested with `v0.1.13`)
- Synaps CLI
- a kitty-graphics-capable terminal supported by terminal-code
